## 🔴 Critique (corrigés dans cette PR)

### 🔴-1 — Fuite de la clé API ElevenLabs dans le bundle client
- **Problème** : la clé secrète était embarquée dans le JavaScript navigateur. `next.config.mjs` copiait `NEXT_ELEVENLABS_API_KEY` dans `NEXT_PUBLIC_ELEVENLABS_API_KEY` via `env:`, et `src/lib/voice.ts` l'envoyait directement à `api.elevenlabs.io` avec l'en-tête `xi-api-key`. N'importe quel visiteur pouvait extraire la clé du bundle et vider le quota ElevenLabs. (Vérifié : avant correction, la chaîne `xi-api-key` était présente dans les chunks client.)
- **Où** : `next.config.mjs` (bloc `env`), `src/lib/voice.ts` (`ELEVENLABS_API_KEY`, appel `fetch` direct), `.env.local.example`, `README.md`.
- **Correction appliquée** : la clé reste strictement côté serveur. Nouvelle route `src/app/api/tts/route.ts` (POST `{ text }` → proxy ElevenLabs, plafond 5 000 caractères, `Cache-Control: no-store`, 204 si pas de clé, 502 sans détail si échec). Le client n'appelle plus que `/api/tts` (`voice.ts` : `speakWithElevenLabs` → `fetch('/api/tts')`). Seul un booléen public `NEXT_PUBLIC_ELEVENLABS_ENABLED` (dérivé de la présence de la clé au build) est exposé au navigateur. Variables d'environnement existantes conservées (`NEXT_ELEVENLABS_API_KEY` côté Vercel, inchangée) ; `.env.local.example` et `README.md` mis à jour pour interdire le préfixe `NEXT_PUBLIC_` sur une clé secrète.
- **Vérification** : après correction, `grep -r "xi-api-key" .next/static/chunks` → aucun résultat ; la chaîne n'existe que dans `.next/server/app/api/tts/route.js`. Comportement identique pour l'utilisateur (ElevenLabs si clé présente, Web Speech API sinon).

### 🔴-2 — localStorage corrompu (JSON valide mais champs invalides) → écran blanc
- **Problème** : si `centeryou-v1` contient du JSON valide mais des entrées malformées (date `"abc"`, heure invalide…), aucun filtre n'existait : `Intl.DateTimeFormat.format(new Date(NaN))` lève un `RangeError` pendant le rendu, sans aucun error boundary → page blanche. (Cas confirmé : `parseISO("abc")` → `Invalid Date` → crash dans `formatDayLong`/`formatDayShort`/`monthMatrix`.) Le cas « JSON illisible » était déjà toléré par zustand v4.5.5 (erreur avalée, retour aux défauts), et le quota plein est avalé silencieusement — mais rien n'empêchait le crash sur données malformées.
- **Où** : `src/lib/store.ts` (option `merge` de `persist`), `src/lib/useHydrated.ts`.
- **Correction appliquée** : sanitation dans `merge` — chaque événement/tâche persisté est validé (id/titre chaînes, date ISO valide, heures `HH:mm`, catégorie/répétition/priorité dans les enums, `createdAt` nombre) et ignoré sinon ; `settings.dayStart` est borné à 6–10. `useHydrated` : `rehydrate()` protégé par `.catch()` pour garantir que l'app quitte toujours l'écran de chargement.
- **Vérification** : `npm run build` ✅, `npm run test:parser` ✅ (tous les tests passent).

## 🟠 Important (à corriger ensuite — listé, non traité ici)

1. **En-têtes de sécurité manquants** — `next.config.mjs` ne définit aucun `headers()` : pas de CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`. *Où* : `next.config.mjs`. *Correction* : ajouter `async headers()` (CSP `default-src 'self'`, `connect-src 'self'`, `img-src 'self' data:`, `frame-ancestors 'none'`, etc. — plus `X-Content-Type-Options: nosniff`).
2. **Pas de mode hors-ligne réel** — `public/` ne contient que le manifest et les icônes ; aucun service worker n'est enregistré, donc une PWA installée ne fonctionne pas hors-ligne. *Où* : `public/manifest.webmanifest`, absence de `sw.js`/enregistrement. *Correction* : service worker de précache (next-pwa ou SW maison) — à planifier, hors « petite correction ».
3. **Contraste insuffisant du teal `text-voice`** — `#2DD4BF` sur fond clair ≈ 1,9:1, sous le seuil WCAG AA (4,5:1) pour le texte : pourcentage de progression (`progress-bar.tsx`), « Lecture en cours » (`welcome-sequence.tsx`), compteurs de la semaine, action des toasts (`toast.tsx`). Design validé → non touché ici. *Correction* : teinte texte plus foncée (ex. `#0F9B8E`) en gardant `#2DD4BF` pour les éléments purement graphiques.
4. **`role="tablist"` incomplet** — `tabs.tsx` : onglets cliquables sans navigation fléchée ni `aria-controls`. *Correction* : ajouter ArrowLeft/Right + `aria-controls`, ou remplacer par de simples boutons.
5. **Dialogue d'accueil sans gestion du focus** — `welcome-sequence.tsx` : focus non déplacé à l'ouverture, Échap actif seulement si le focus est dans la boîte, et les raccourcis globaux (`app-shell.tsx`) restent actifs derrière. *Correction* : focus initial + piège de focus comme dans `ui/dialog.tsx`.
6. **Quota localStorage plein silencieux** — zustand v4.5.5 avale l'erreur : l'état reste en mémoire mais n'est plus persisté, sans avertissement. *Correction* : wrapper de storage avec `try/catch` + toast « stockage plein ».
7. **Route `/api/tts` appelable par tous** — la clé est protégée, mais n'importe quel visiteur peut consommer le quota ElevenLabs via la route. *Correction* : rate-limit (Vercel Edge/middleware) ; le plafond de 5 000 caractères est déjà en place.

## 🟪 Amélioration (à noter)

1. **Duplication** : `nextSlot()` défini 3 fois (`app-shell.tsx:16`, `event-dialog.tsx:23`, `planning/page.tsx:23`) ; `selectClass` 2 fois (`event-dialog.tsx:30`, `reglages/page.tsx:13`). → extraire dans `lib/dates.ts` / un composant UI partagé.
2. **Code mort** : `layout.sidebarW`, `layout.topbarH`, `layout.shellMaxW`, `layout.dayStartDefault` (`design/tokens.ts`) et `priorityColor` (`lib/categories.ts:30`) inutilisés ; `DAY_START`/`DAY_END` (`lib/dates.ts:1-2`) redoublent `layout.dayStartDefault`/`dayEnd`.
3. **Tri mutant dans le render** : `todayTasks.sort(...)` (`app/page.tsx`) mute le tableau mémoïsé → copier avant tri.
4. **Recalculs non mémoïsés** : `calendarOnDate` appelé par jour dans `week-view.tsx` et `calendarMonthOnDate` × 42 dans `month-view.tsx` (données locales, impact faible).
5. **Textes FR / cas limites** : « Tes 1 prochains rendez-vous » (`welcome-sequence.tsx`) ; « . Et . » (`voice-commands.ts`) ; fin à minuit (`00:00`) impossible dans le dialogue (`event-dialog.tsx`, `minutesOf(end) <= minutesOf(start)`) ; événement à 00h00 affiché en haut de grille (`event-block.tsx`, `top` borné à 0). Chevauchements partiels autorisés avec avertissement (choix assumé, documenté dans l'UI).
6. **`Field` trompeur** — pose un `id` sur le `<span>` au lieu d'un `for` sur le `<label>` (`ui/input.tsx`) ; l'association implicite fonctionne, l'attribut est inutile.
7. **360 px** : vues Semaine (`min-w-[720px]`) et Mois (`min-w-[560px]`) en défilement horizontal (acceptable avec `overflow-x-auto`) ; le reste tient à 360 px.
8. **Manifest** : `orientation: "portrait"` forcée même en installation desktop ; pas de `serviceworker` (voir 🟠-2).
9. **`X-Powered-By`** non masqué (`poweredByHeader` absent de `next.config.mjs`).

## ✅ Points positifs constatés

- **Sécurité** : aucun `dangerouslySetInnerHTML` / `innerHTML` / `eval` ; toutes les saisies utilisateur rendues via React (échappement automatique) ; `maxLength` sur tous les champs (30/80/140) ; date/heure via inputs natifs ; aucune donnée sensible dans le localStorage (uniquement événements, tâches, réglages) ; aucun cookie.
- **Fiabilité** : JSON illisible → retour propre aux défauts (vérifié dans `zustand@4.5.5`) ; rehydratation désormais protégée par `.catch` ; entrées malformées filtrées ; bascule automatique Web Speech API si ElevenLabs indisponible ; aucune erreur bloquante dans les commandes vocales.
- **Performance** : build mesuré — First Load JS ≈ 99–106 kB par page (partagé 87,3 kB) ; mois tronqué à 3 items + « +N » ; pas de listes longues non virtualisées (données 100 % locales).
- **Accessibilité** : cibles tactiles ≥ 44 px (`min-h-11`), `focus-visible` partout, piège de focus + Échap dans `ui/dialog.tsx`, `aria-label` riches sur les blocs d'événements, `role="progressbar"`, `aria-live` sur toasts/voix, `prefers-reduced-motion` global, `lang="fr"`.
